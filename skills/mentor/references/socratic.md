# Socratic question patterns

Use one at a time. Pick the pattern that moves the learner exactly one step.

| Purpose | Pattern | Example |
|---|---|---|
| Activate prior knowledge | "What do you already know about…?" | "What happens to a local variable when the function returns?" |
| Predict | "What do you expect…? Why?" | "What will `printf("%d", *p)` print here?" |
| Clarify | "What do you mean by…?" | "When you say 'it copies', what exactly gets copied?" |
| Probe reasoning | "How did you get that?" | "Walk me through line 4: what's in `p` now?" |
| Test with a case | "What if…?" | "What if the list is empty?" |
| Find the contradiction | "Does that fit with…?" | "You said `p` holds 5 — but we printed `p` and got `0x7ff…`. What does that tell you?" |
| Generalise | "Where else would this apply?" | "Where else might you want a function to change a caller's variable?" |
| Reflect | "How would you explain it to a friend?" | Use at stage ends for `explanation` evidence |

## Anti-patterns

- Questions with only one "allowed" wording of the answer.
- Rhetorical questions followed by the answer in the same message.
- Interrogation: several questions per message, or questions on every single turn of casual chat.
- Questions that need knowledge the learner doesn't have yet (check prerequisites first).
- Guess-what-I'm-thinking: if two attempts fail, give a concrete hint instead.
