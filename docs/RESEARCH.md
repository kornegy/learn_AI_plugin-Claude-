## 0. Короткий ответ

1. **Идея реализуема, но не одинаково на всех поверхностях Claude.** В Claude Code и Cowork
   (агентный режим Claude Desktop) работает всё: автозагрузка профиля в новую сессию,
   локальные файлы, хуки, сабагенты, MCP-сервер. В обычном чате claude.ai (web, mobile, чат
   Claude Desktop) плагин загружает **только skills и commands**. Хуки, сабагенты и локальные
   MCP-серверы там игнорируются. Поэтому полноценная «память в новых чатах» в обычном чате
   без отдельного сервера невозможна.
2. **«Автоматически анализировать предыдущий контекст» в буквальном смысле нельзя.** У плагина
   нет API для чтения прошлых чатов. Встроенный в claude.ai поиск по прошлым чатам недоступен
   плагинам программно и не даёт структурированных данных. Рабочая модель другая:
   **Claude записывает учебные доказательства по ходу диалога** через инструменты плагина,
   а **хук `SessionStart` автоматически подгружает компактную «карточку ученика»** в начало
   каждой новой сессии. Для пользователя это выглядит как «Claude меня помнит», и при этом
   ничего не выдумывается.
3. **Рекомендуемая архитектура — плагин Claude Code / Cowork с локальным MCP-сервером на
   TypeScript.** Сервер владеет данными: валидирует их, пишет атомарно, проверяет пути,
   детерминированно считает уровни и повторения. Методику задают skills, автоматизацию —
   хуки. Данные лежат в Markdown-файлах с YAML-заголовком в четырёх папках, как в ТЗ, плюс
   служебная папка `.mentor/` (журнал событий, версия схемы, резервные копии).
4. **С тремя пунктами ТЗ я не согласен, ниже предлагаю альтернативы:**
   - глобальный запрет на готовый код опасен в Claude Code: плагин сломает обычную рабочую
     разработку. Нужна явная активация учебного режима;
   - абсолютный запрет на любой код вреден новичкам (эффект «worked example»). Предлагаю
     «лестницу подсказок» с настраиваемой строгостью: готовое решение задачи запрещено всегда,
     но примеры на *аналогичной* задаче допустимы;
   - четыре уровня оставляем для пользователя, но внутри нужна модель доказательств
     (evidence) и отдельная от уровня модель забывания. Иначе «стоит повторить» смешивает
     два разных явления.
5. **Выпуск:** отдельный публичный GitHub-репозиторий, который одновременно служит
   маркетплейсом (`.claude-plugin/marketplace.json`) → бета через собственный маркетплейс →
   подача в Anthropic Directory. Одна запись в каталоге доходит до claude.ai, Cowork и Claude
   Code (в чате плагин работает в урезанном режиме).

## 2. Экосистема Claude на ноябрь 2026 (только то, что важно проекту)

### 2.1. Три поверхности

| Поверхность | Что это | Важно для нас |
|---|---|---|
| **Чат** | claude.ai web, чат Claude Desktop, мобильные приложения | Skills (нужно включить «Code execution and file creation»), Projects, встроенная память и поиск по прошлым чатам, коннекторы (remote MCP). Плагины ставятся через **Customize → Plugins**, но загружаются только skills и commands |
| **Cowork** | Агентный режим в Claude Desktop на архитектуре Claude Code | Читает и пишет локальные файлы, загружает skills, commands, agents, hooks и локальные MCP (когда сессия идёт на компьютере пользователя). Плагины берутся из аккаунта claude.ai, а не из `~/.claude` |
| **Claude Code** | CLI, IDE-расширения, вкладка Code в Desktop | Загружает всё: skills, commands, agents, hooks, MCP, output styles, `settings`, `bin/` |

Официальная таблица поддержки компонентов (claude.com/docs/plugins/platform-support):

| Компонент | Chat | Cowork | Claude Code |
|---|---|---|---|
| Skills | загружается | загружается | загружается |
| Commands | загружается как skill | `/plugin:command` | загружается |
| Agents (сабагенты) | игнорируется | загружается | загружается |
| Hooks | **игнорируется** | загружается | загружается |
| Remote MCP (http/sse) | через вкладку Connectors | загружается | загружается |
| Local MCP (stdio, `.mcpb`) | **игнорируется** | загружается, если сессия на компьютере | загружается |
| MCP с `${user_config.*}` | игнорируется | игнорируется, если у опции нет default | спрашивает значения |
| `bin/` в корне | **плагин нельзя установить** | **нельзя установить** | загружается |
| Output styles, LSP, themes, settings | игнорируется | игнорируется | загружается |

**Следствия для дизайна:**
- папку `bin/` в корне не использовать, иначе плагин не установится в claude.ai и Cowork;
- у всех `userConfig` должны быть значения по умолчанию, потому что Cowork не спрашивает;
- всё, без чего продукт не работает, кладём в skills. Хуки и MCP — это усилители;
- frontmatter skills делаем переносимым: при загрузке в claude.ai допустимы только `name`,
  `description`, `license`, `compatibility`, `metadata`, `allowed-tools`, а остальные ключи
  дают ошибку.

### 2.2. Механизмы расширения и их роль в проекте

| Механизм | Как работает (по документации) | Роль в продукте |
|---|---|---|
| **Skills** (`skills/<name>/SKILL.md`) | В контексте всегда только `name` + `description` (до 1536 символов). Полный текст загружается, когда запрос подходит под описание, и остаётся в диалоге. После компакции сохраняются первые ~5000 токенов последнего вызова (общий бюджет 25 000). Дополнительные файлы читаются по необходимости. Открытый стандарт Agent Skills | **Ядро методики:** протокол сессии, Сократ, аналогии, этапы, оценка, наставник по коду. SKILL.md держим < 5k токенов, детали — в `references/` |
| **Commands** (`commands/*.md`) | Слеш-команды `/learning-mentor:start`. В чате работают как skill | Явные действия пользователя: start, status, plan, review, export, forget, settings |
| **Hooks** | События: `SessionStart` (matcher `startup/resume/clear/compact/fork`), `UserPromptSubmit`, `Stop`, `PreCompact`, `PostCompact`, `SessionEnd` и др. Типы: `command`, `http`, `mcp_tool`, `prompt`, `agent`. `SessionStart` поддерживает только `command` и `mcp_tool`. `additionalContext` ≤ 10 000 символов. **Писать его как факты, а не как императивные инструкции**, иначе защита от prompt injection может его отбросить. `SessionEnd` получает 1,5 с общего бюджета | **Автоматизация памяти:** `SessionStart` подгружает карточку ученика, на `compact` подгружает её заново. `UserPromptSubmit` (фаза 4) напоминает о контрольной точке |
| **MCP** | stdio-сервер из плагина (`.mcp.json`) получает `CLAUDE_PLUGIN_ROOT` и `CLAUDE_PLUGIN_DATA` | **Хранилище и движок:** типизированные инструменты, валидация, атомарная запись, расчёт уровней и повторений |
| **Subagents** (`agents/*.md`) | Отдельный контекст, свой системный промпт и набор инструментов, возвращает сводку | **Исследователь источников:** читает недоверенный веб в изолированном контексте |
| **Output styles** | Инструкции на каждый ответ сессии. Можно положить в плагин. `force-for-plugin: true` навязывает стиль во всех сессиях | Опциональный стиль «Mentor» для учебных папок. **`force-for-plugin` не используем**, см. §5.1 |
| **userConfig** | Значения, которые Claude Code спрашивает при включении плагина. Типы `string/number/boolean/directory/file`, хранятся в `settings.json` | Только `data_dir` (с default). Остальные настройки — в файле конфигурации в папке данных, чтобы они работали на всех поверхностях |
| **`${CLAUDE_PLUGIN_DATA}`** | `~/.claude/plugins/data/<id>/`, сохраняется при обновлениях, **но удаляется при деинсталляции** | **Не годится для учебной истории:** её можно потерять. Используем для кэша, данные ученика храним отдельно, см. §6.3 |
| **Plugin evals** (`claude plugin eval`) | Кейсы `prompt.md` + грейдеры (`regex`, `tool_used`, `tool_order`, `file_exists`, `llm`, `baseline`). Сравнение с прогоном без плагина. Продолжение диалога через `context.history_file`. Песочница, `--max-cost-usd`. Своих кодовых грейдеров нет | **Тесты педагогического поведения** (см. §11) |
| **Marketplace** | `.claude-plugin/marketplace.json` в git-репозитории. Установка: `claude plugin marketplace add owner/repo` + `claude plugin install name@marketplace` | Канал беты и обновлений |
| **Anthropic Directory** | Подача через claude.ai/directory/manage (нужен платный план). Одна запись доступна в claude.ai, Cowork и Claude Code (как `<name>@synced`) | Публичный релиз |
| **MCPB** (`.mcpb`) | Локальный MCP-сервер в zip, ставится в Claude Desktop одним кликом. Node.js встроен в Desktop. В Directory MCPB больше не принимают — только внутри плагинов | Опциональный путь к памяти в чате Claude Desktop (фаза 4, проверить) |

### 2.3. Что уже есть в самой экосистеме Claude

- **Learning mode в claude.ai.** Сократический стиль: появился в Claude for Education
  (апрель 2025), потом стал доступен всем пользователям. Включается в меню стилей, не помнит
  ученика и не ведёт учёт знаний.
- **Output style «Learning» в Claude Code.** Claude делает задачу сам, но оставляет
  пользователю небольшие куски с реальными решениями (`TODO(human)`) и добавляет блоки
  `Insight`. Подход «научись по ходу работы», а не «научись сам»: прогресс не хранит, оценки нет.
- **Память и поиск по прошлым чатам в claude.ai.** Неструктурированная память о
  пользователе, поиск по чатам по запросу. Плагинам программно недоступна.

Это важно для позиционирования: «Claude задаёт наводящие вопросы» уже есть бесплатно.
**Наша ценность в другом:** долговременная, прозрачная, доказательная модель знаний ученика,
маршруты с пререквизитами, повторение по расписанию и строгий наставник по программированию
поверх этой модели.

## 3. Главный вопрос: работа в новых чатах и анализ прошлого контекста

### 3.1. Что физически возможно

| Механизм | Есть ли | Ограничение |
|---|---|---|
| Прочитать прошлый чат claude.ai из плагина | ❌ | API нет |
| Встроенный поиск по прошлым чатам claude.ai | ✅ у пользователя | Ответ свободным текстом, не структура; плагин его не вызывает |
| Внедрить контекст в начало сессии Claude Code / Cowork | ✅ `SessionStart` | ≤ 10k символов, писать фактами |
| Прочитать транскрипт сессии Claude Code | ✅ `transcript_path` в хуках | Файл пишется асинхронно; анализ нужен моделью, это стоит денег и требует отдельного вызова LLM |
| Заставить модель «подвести итог» при выходе | ❌ | `SessionEnd` не может продолжить диалог, бюджет 1,5 с |
| Модель сама сохраняет выводы по ходу диалога | ✅ MCP-инструменты + инструкции skill | Зависит от дисциплины модели; страхуем хуками и evals |

### 3.2. Рекомендуемая модель: «записывай по ходу, подгружай на старте»

```
          новая сессия                         учебный диалог                          конец / компакция
 ┌──────────────────────────┐   ┌──────────────────────────────────────────┐   ┌────────────────────────┐
 │ SessionStart hook (node) │   │ skill "mentor" ведёт урок                │   │ на compact:            │
 │ читает файлы напрямую    │──▶│  ├─ проверка пререквизитов               │──▶│ SessionStart(compact)  │
 │ → карточка ученика       │   │  ├─ этап → вопрос → ответ ученика        │   │ подгружает карточку    │
 │   (≤ ~2k токенов, факты) │   │  └─ значимое событие ──▶ MCP:            │   │ заново                 │
 └──────────────────────────┘   │      record_evidence / advance_stage     │   └────────────────────────┘
                                │      (сервер валидирует, считает уровень,│
                                │       пишет атомарно, журналирует)       │
                                └──────────────────────────────────────────┘
```

- **Карточка ученика** — компактная сводка *фактов*, например: «Активная дисциплина: C++.
  Текущий этап: указатели, этап 5 из 8 (разыменование). К повторению: ссылки (просрочено на
  3 дня). Повторяющееся заблуждение: путает `*p` и `&x`. Последняя сессия: 2026-10-28». Всё
  подробнее Claude запрашивает инструментами по необходимости, так экономится контекст.
- **Что считать значимым событием**, определяет skill: правильное объяснение своими словами,
  самостоятельное решение, повторившаяся ошибка, завершение этапа, смена темы. Каждое
  сообщение **не** записывается. Бытовые и посторонние вопросы не записываются.
- **Страховка от «забыла записать»:**
  1. фаза 3 — повторная подгрузка карточки после компакции (`SessionStart`, matcher `compact`);
  2. фаза 4 — дешёвый детерминированный хук `UserPromptSubmit`: если учебная сессия идёт
     больше N реплик или минут без записи в журнал, он добавляет одну строку-факт
     «последняя контрольная точка была 25 минут назад». LLM при этом не вызывается;
  3. фаза 4 — опциональная команда `/learning-mentor:reflect`: с явного согласия пользователя
     Claude перечитывает транскрипт текущей или прошлой сессии Claude Code и восполняет
     пропущенные записи. Это и есть «анализ предыдущего контекста», но честный и по запросу.

### 3.3. Почему не анализировать каждый диалог фоновым LLM-вызовом

Технически можно: хуки `prompt` и `agent`, или собственный вызов API из хука. Но:
- дорого: лишний вызов модели на каждой остановке;
- нужен API-ключ или квоты пользователя — плохо для массового продукта;
- приватность: транскрипт уходит в ещё один вызов;
- качество хуже, чем у основной модели, которая видела весь диалог и сама вела урок.

**Решение:** оценку делает основная модель в момент события. Код лишь применяет
детерминированные правила к её классификации (см. §6.4).

### 3.4. Что делать с обычным чатом claude.ai

| Вариант | Память между чатами | Сложность | Приватность | Рекомендация |
|---|---|---|---|---|
| A. Только skills (методика), без памяти | ❌ | низкая | ✅ | **Да, в v1.0 бесплатно, плагин в чате работает так сам** |
| B. Снимок профиля: `/learning-mentor:export --snapshot` → файл в claude.ai Project | ⚠️ только чтение, вручную | низкая | ✅ | Да, фаза 4 |
| C. `.mcpb` для чата Claude Desktop (тот же сервер) | ✅ macOS/Windows | средняя | ✅ локально | Фаза 4, после проверки (spike S3) |
| D. Remote MCP с хостингом и аккаунтами | ✅ везде, включая mobile | высокая: OAuth, БД, сервер, деньги | ⚠️ данные у нас | Не в v1. Возможно v2 с self-host |

## 4. Обзор похожих решений

| Решение | Что делает | Чего не хватает относительно нашей идеи |
|---|---|---|
| Claude Learning mode (claude.ai) | Сократический стиль ответа | Нет памяти, оценки, маршрутов |
| Claude Code output style «Learning» | `TODO(human)` и Insight-блоки при реальной работе | Не ведёт учёт знаний, задачу в итоге делает Claude |
| ChatGPT Study Mode (июль 2025) | Сократический диалог, вопросы на понимание | Закрытый, нет прозрачной модели знаний, нет локальных данных |
| Gemini Guided Learning (август 2025) | Пошаговые уроки, визуализации, квизы | То же |
| Khanmigo (Khan Academy) | Тьютор, который не даёт ответов, привязан к курсам Khan | Привязан к своей программе, не к произвольным темам |
| [claude-tutor](https://github.com/kirilxd/claude-tutor) (open source, MIT, ~144★) | Плагин Claude Code: `/learn`, `/quiz`, `/review`, SM-2, JSON в `~/.claude/learning/`, веб-дашборд, хуки SessionStart/PreToolUse | Упор на квизы и флеш-карты; JSON вместо читаемых записей; SM-2 вместо FSRS; нет модели доказательств понимания и наставника по коду с запретом решений. Данные лежат внутри `~/.claude` |
| Academy MCP (StudioMeyer) | MCP: уроки, квизы, повторение | Нужен аккаунт и API-ключ, состояние на сервере |
| Anki + FSRS | Эталон интервального повторения | Только карточки, без обучения |

**Вывод:** ниша «тьютор + повторение» в экосистеме уже занята минимум одним открытым
плагином. Мы отличаемся так:
1. **доказательная оценка понимания** (типы доказательств, предварительные уровни, без
   повышения за «прочитал»), а не баллы за квиз;
2. **граф тем с пререквизитами** и проверка базовых знаний перед новой темой;
3. **наставник по программированию** с 7 этапами и лестницей подсказок;
4. **прозрачные Markdown-записи**, которые человек может читать, править и хранить в git;
5. **библиотека источников** с версиями технологий, датами проверки и TTL;
6. **работа на Claude Code и Cowork** с честной деградацией в чате.

Изучить код claude-tutor перед реализацией стоит (MIT-лицензия): там решены похожие задачи
с хуками и есть пример набора evals.

### 4.1. Педагогическая база (на что опирается методика)

Это классические и широко воспроизведённые результаты. Ссылки — на первоисточники по автору
и году. В рамках этого исследования они не перепроверялись онлайн, перепроверю при
написании PRODUCT_SPEC.

| Принцип | Источник | Что берём |
|---|---|---|
| Mastery learning | Bloom, 1984 («2 Sigma Problem») | Не идти дальше без освоения базы |
| Retrieval practice | Roediger & Karpicke, 2006 | Проверять вспоминанием, а не перечитыванием |
| Spacing effect | Cepeda et al., 2006 | Интервальное повторение |
| FSRS | open-spaced-repetition (Ye et al.) | Расписание повторений лучше SM-2 при той же нагрузке |
| Self-explanation | Chi et al., 1989/1994 | «Объясни своими словами» — сильное доказательство |
| Worked-example effect / expertise reversal | Sweller; Kalyuga et al., 2003 | **Новичкам разобранные примеры нужны, опытным мешают** → адаптивная строгость |
| Productive failure | Kapur, 2008+ | Сначала дать попробовать, потом объяснять |
| Knowledge tracing | Corbett & Anderson, 1994 (BKT) | Уровень как оценка с неопределённостью |
| Misconceptions | Литература по концептуальному изменению | Отслеживать устойчивые заблуждения отдельно от ошибок |

## 5. Где я не согласен с ТЗ и что предлагаю

### 5.1. «Каждый учебный диалог автоматически» ↔ Claude Code — инструмент работы

Плагин ставится в Claude Code на уровне пользователя. Если правило «не писать готовый код»
будет действовать всегда, Claude перестанет писать код и в рабочих проектах пользователя.
Это сломает основной инструмент.

**Предлагаю явную, но лёгкую активацию:**
- **учебная папка (workspace):** `/learning-mentor:start` создаёт или отмечает папку маркером
  `.learning-mentor.json`. Внутри неё (и в Cowork-проекте с этой папкой) хук `SessionStart`
  подгружает карточку, а режим наставника включён по умолчанию;
- **вне учебной папки** хук молчит. Skill «mentor» всё равно доступен по описанию: фраза
  «объясни мне указатели, хочу разобраться» его активирует, и Claude спросит, вести ли это как
  урок с сохранением прогресса;
- **явный выход:** «сейчас мне нужен просто рабочий код» в учебной папке → Claude соглашается,
  отмечает это и не превращает в урок. Автономия пользователя важнее методики.

### 5.2. Абсолютный запрет на код → лестница помощи

Полный запрет на любой код противоречит эффекту разобранных примеров: новичок, который не
видел ни одного корректного цикла, не «откроет» синтаксис сократическими вопросами, а
выгорит. Поэтому:

| Ступень | Что Claude может дать | Когда |
|---|---|---|
| 0 | Вопрос, переформулировка задачи | Всегда сначала |
| 1 | Концептуальная подсказка, аналогия | После попытки |
| 2 | Псевдокод или план шагов, **составленный вместе** | Застрял на логике |
| 3 | Синтаксис отдельной конструкции на **абстрактном** примере (2–5 строк, не из задачи) | Не знает конструкцию языка |
| 4 | Разобранный пример **аналогичной, но другой** задачи, иногда с пропусками | Уровень «не знаю совсем», повторные неудачи |
| 5 | Указание на строку с ошибкой и вопрос «что здесь происходит?» | Отладка его кода |
| ✗ | **Готовое решение исходной задачи** или реализация требуемой функциональности | **Никогда** в учебном режиме |

Строгость (`assistance_level: strict | balanced | supportive`) определяет, как быстро Claude
поднимается по лестнице. Отказ никогда не бывает «сухим»: протокол из ТЗ (начать с простого,
объяснить пользу, аналогия, декомпозиция) остаётся.

### 5.3. Четыре уровня ↔ модель доказательств и забывание

Шкала из ТЗ хороша для пользователя, но в ней склеены два измерения:
- **понимание**: насколько глубоко понял («слабое», «хорошо знаю»);
- **удержание**: не забыл ли со временем («стоит повторить»).

Человек может глубоко понимать указатели и при этом не повторять их полгода. Предлагаю:
- **хранить уровень понимания** (1–4) с флагом `provisional` и **журналом доказательств**;
- **отдельно хранить состояние памяти** (FSRS: стабильность, дата следующего повторения);
- уровень 2 «Стоит повторить / закрепить» ставить по доказательствам: была база, но проверка
  показала забывание или путаницу. Само наступление даты повторения уровень не меняет;
- в интерфейсе показываем одну понятную строку: «Указатели — Есть понимание, но слабое ·
  повторить до 3 ноября».

### 5.4. Исследование источников перед каждой новой темой → по необходимости

Полное исследование перед каждой темой — это минуты задержки и лишние токены, а для
«что такое переменная» пользы нет. Правило:
- исследовать, когда тема **версионная** (библиотеки, языки, стандарты, API), когда
  пользователь просит, когда в библиотеке нет записи или **истёк TTL**, и когда Claude не
  уверен в факте;
- TTL зависит от домена: быстро меняющиеся технологии — 90 дней, стабильные языки и
  стандарты — 365, фундаментальные науки — 3 года;
- без интернета честно говорим об этом и используем кэш с пометкой о свежести.

### 5.5. Хранение «Markdown в четырёх папках» — оставляем, но дополняем

Markdown с YAML-заголовком сохраняет читаемость, и при этом структуру можно проверить
программно. Дополнения:
- `.mentor/` — версия схемы, конфигурация, **append-only журнал событий** (JSONL), резервные
  копии, карантин повреждённых файлов. Историю обучения не пишем внутрь тем: она в журнале и
  не перезаписывается;
- по умолчанию корень данных лежит **не** в `${CLAUDE_PLUGIN_DATA}` (удаляется вместе с
  плагином), а в видимой папке пользователя, см. §6.3.

## 6. Предлагаемая архитектура

### 6.1. Компоненты

```
┌──────────────────────────────────── Плагин learning-mentor ─────────────────────────────────────┐
│                                                                                                  │
│  skills/ (методика, работают на ВСЕХ поверхностях)        commands/ (явные действия)             │
│   ├─ mentor        протокол урока, Сократ, аналогии,       start · status · plan · review ·      │
│   │                этапы, стиль общения                    research · export · forget · settings │
│   ├─ assess        рубрика доказательств и уровней                                               │
│   ├─ code-mentor   7 этапов программирования, лестница                                           │
│   └─ research      политика источников, анти-injection     agents/researcher.md  (Code, Cowork)  │
│                                                             изолированный веб-исследователь      │
│  hooks/hooks.json (Code, Cowork)                                                                 │
│   ├─ SessionStart  → node hook.mjs session-start   (карточка ученика, только в учебной папке)    │
│   └─ UserPromptSubmit → node hook.mjs checkpoint-nudge   (фаза 4)                                │
│                                                                                                  │
│  .mcp.json → node server/dist/mentor-mcp.mjs  (Code, Cowork; Desktop-чат через .mcpb — фаза 4)   │
│   ┌───────────────────────────── mentor-core (TypeScript) ──────────────────────────────┐        │
│   │ schemas (zod) │ storage (атомарная запись, блокировки, path guard, журнал, бэкапы) │        │
│   │ mastery engine (правила уровней) │ scheduler (FSRS) │ path engine (DAG тем)        │        │
│   │ research cache (TTL, версии) │ migrations │ export / delete │ doctor (проверка)    │        │
│   └──────────────────────────────────────────────────────────────────────────────────────┘        │
│  output-styles/mentor.md (опционально, только Claude Code, только по выбору пользователя)        │
└──────────────────────────────────────────────────────────────────────────────────────────────────┘
                     │ читает/пишет только внутри корня данных
                     ▼
              ~/LearningMentor/   (learner-profile/ knowledge-base/ learning-paths/ research-library/ .mentor/)
```

**Разделение ответственности:**
- **Модель (skills)** решает педагогические вопросы: что спросить, какую аналогию взять, как
  классифицировать ответ ученика (тип доказательства, ошибка или заблуждение).
- **Код (mentor-core)** отвечает за то, что должно быть детерминированным и проверяемым:
  формат данных, правила перехода уровней, расписание повторений, порядок тем, даты (модель не
  знает точную текущую дату — её даёт сервер), безопасность файлов.
- **Хуки** делают то, что должно происходить без участия модели: подгрузку карточки.

### 6.2. Сравнение вариантов хранения и доступа к данным

| Критерий | A. Только skills, Claude правит .md своими Read/Write | **B. Skills + локальный MCP-сервер** | C. SQLite + MCP | D. Remote MCP |
|---|---|---|---|---|
| Надёжность формата | ❌ дрейф формата, порча при частичной записи | ✅ схема + атомарность | ✅ | ✅ |
| Читаемость пользователем | ✅ | ✅ | ❌ | ❌ |
| Детерминированные правила уровней и FSRS | ❌ «на глаз» модели | ✅ | ✅ | ✅ |
| Работа в Cowork | ✅ | ✅ | ✅ | ✅ |
| Работа в Desktop-чате | ❌ | ⚠️ через `.mcpb` | ⚠️ | ✅ |
| Проверка путей, защита от удаления | ❌ инструкциями | ✅ кодом | ✅ | ✅ |
| Тестируемость | ❌ только evals | ✅ unit + integration + evals | ✅ | ✅ |
| Сложность поддержки | минимальная | средняя | средняя | высокая |
| Приватность | ✅ | ✅ | ✅ | ⚠️ |

**Выбор: B.** Вариант A проще, но для продукта на тысячи пользователей ненадёжен: любая ошибка
модели портит профиль. C теряет главное свойство — человекочитаемость. D — для v2.

### 6.3. Где лежат данные

- По умолчанию `~/LearningMentor/`. Папка видимая, принадлежит пользователю, её можно
  положить в git или облачный диск. В Claude Code её можно переопределить через `userConfig`
  `data_dir` (тип `directory`, с default), в Cowork — подключить как папку проекта.
- В `${CLAUDE_PLUGIN_DATA}` лежит только кэш (например, собранный индекс). Его потеря не страшна.
- **Изоляция пользователей:** один корень данных — один ученик. На общей машине у каждого
  пользователя ОС свой `~`. Несколько профилей у одного пользователя ОС — через разные
  `data_dir`. Сервер никогда не читает за пределами корня.

### 6.4. Модель знаний (ядро продукта)

**Типы доказательств** (модель классифицирует, код взвешивает):

| Тип | Пример | Вес | Может поднять до |
|---|---|---|---|
| `exposure` | Прочитал объяснение | 0 | — (уровень не меняется, ТЗ: «не повышай за чтение») |
| `self_report` | «Я это знаю» | 0 | ставит уровень с `provisional: true`, нужна проверка |
| `recognition` | Выбрал верный вариант | низкий | 2 (угадывание не доказательство) |
| `recall` | Сам вспомнил определение или факт | низкий/средний | 3 |
| `explanation` | Объяснил своими словами корректно | средний | 3 |
| `application` | Решил задачу сам (флаг `assisted` снижает вес) | высокий | 4 |
| `transfer` | Применил в новом контексте, нашёл и объяснил ошибку, научил | максимальный | 4 |
| `error` (`slip` / `misconception`) | Ошибка: случайная или системная | отрицательный | — |

**Правила уровней** (стартовая версия, пороги зависят от настройки `assessment_strictness`):
- **4 «Хорошо знаю»:** ≥ 1 `transfer` **или** ≥ 2 самостоятельных `application` в **разных
  сессиях**; плюс ≥ 1 `explanation`; нет открытых `misconception`.
- **3 «Есть понимание, но слабое»:** есть `explanation` или `assisted application`, но нет
  самостоятельного применения.
- **2 «Стоит повторить / закрепить»:** раньше было ≥ 3, но свежая проверка показала забывание
  (неудачный `recall` после перерыва) **или** ≥ 2 ошибки по разным пунктам за проверку.
- **1 «Не знаю совсем»:** доказательств нет или не может объяснить назначение концепции.
- **Понижение:** одна `slip` уровень **не** понижает (ТЗ). Нужны ≥ 2 независимые неудачи или
  повторившееся заблуждение.
- **`provisional: true`**, пока доказательств меньше порога. Карточка показывает это как «(предварительно)».
- Модель может предложить ручное переопределение с обоснованием. Оно попадает в журнал.

**Заблуждения** отслеживаются отдельно (`misconceptions/` внутри темы) и связываются между
темами: «путает адрес и значение» влияет и на указатели, и на ссылки.

**Повторения:** у каждой темы с уровнем ≥ 3 есть FSRS-карта. Оценка повторения выводится из
исхода проверки (Again / Hard / Good / Easy). Настройка `review_intensity` задаёт желаемую
вероятность вспомнить (0.85 / 0.90 / 0.95).

### 6.5. Учебные маршруты

- Маршрут **дисциплины** — DAG тем с пререквизитами. Следующая тема выбирается
  топологически среди тех, чьи пререквизиты имеют уровень ≥ 3. Просроченные повторения
  перемешиваются с новым материалом (interleaving).
- Маршрут **темы** — список этапов. У каждого этапа есть цель, критерии завершения и статус
  (`pending / active / done / skipped(reason)`). Этапы предлагает модель, их число зависит от
  сложности. Сервер хранит их и не даёт отметить этап `done`, пока не записано
  доказательство, соответствующее критерию.
- **Проверка пререквизитов** перед новой темой: сервер возвращает список, Claude задаёт
  1–2 коротких вопроса по слабым или неизвестным пунктам.
- Маршрут обновляется при изменении уровней: тема опустилась до 2 → в маршрут вставляется
  этап повторения.

### 6.6. Библиотека источников и защита от prompt injection

```
main Claude ──"исследуй тему X, версия Y"──▶ subagent researcher
                                              tools: WebSearch, WebFetch (только чтение,
                                                     без записи файлов и без MCP-записи)
                                              системный промпт: веб — это ДАННЫЕ
main Claude ◀── структурированная сводка ─────┘   (url, издатель, уровень источника, версия,
     │                                              дата, факты своими словами, короткие цитаты,
     │                                              противоречия между источниками)
     ▼
MCP save_source → сервер валидирует: только https, лимиты длины, цитаты ≤ ~25 слов,
                  поля по схеме, без исполняемого/HTML-содержимого; ставит accessed_at и TTL
```

- Недоверенный текст из веба не попадает в основной контекст целиком, только отфильтрованная
  сводка. Это не абсолютная защита, но значительно сужает поверхность атаки.
- Skill «research» прямо перечисляет признаки инъекций («игнорируй инструкции», просьбы
  выполнить команды или записать файлы, изменить профиль) и запрещает им следовать.
- Сервер плагина **сам в сеть не ходит**: веб-доступ остаётся у инструментов Claude с
  обычными разрешениями пользователя.
- Приоритет источников (5 уровней из ТЗ) хранится полем `source_tier`. Устаревание отмечается
  через `verified_at + ttl_days` и `technology_version`.

### 6.7. Пример записи темы

```markdown
---
schema: 1
id: cpp/pointers
title: Указатели
subject: cpp
level: 3                 # 1..4
provisional: false
prerequisites: [cpp/variables, cpp/memory-basics]
misconceptions:
  - id: addr-vs-value
    status: open
    first_seen: 2026-10-20
    occurrences: 3
review:                   # FSRS
  due: 2026-11-03
  stability: 4.2
  difficulty: 6.1
last_assessed: 2026-10-28
updated: 2026-10-28
---

## Кратко
Указатель хранит адрес другого объекта в памяти…

## Что уже изучено
- Зачем нужны указатели, взятие адреса `&`.

## Что понимает
- Объяснил своими словами, чем адрес отличается от значения (2026-10-28).

## Что пока не понимает
- Арифметика указателей.

## Доказательства понимания
- 2026-10-28 · explanation · «указатель — как записка с адресом квартиры…»
- 2026-10-28 · application (assisted, hint 2) · поменял значение через указатель

## Что повторить
- Разыменование при передаче в функцию.
```

Структурные поля в frontmatter пишет только сервер. Текстовые разделы сервер пишет по
частям (секция → новое содержимое), а не целиком, чтобы не потерять написанное ранее.

## 7. Технологический стек

| Слой | Выбор | Обоснование | Отвергнутые альтернативы |
|---|---|---|---|
| Язык сервера и хуков | **TypeScript (Node.js ≥ 20)** | Эталонный MCP SDK. Node встроен в Claude Desktop (MCPB). Хуки на Node работают на Windows без bash/jq | Python (нужен `uv`/python у пользователя, на Windows хуже); Go/Rust (бинарники под платформы, а `bin/` запрещён на claude.ai/Cowork) |
| MCP | `@modelcontextprotocol/sdk` (stdio) | Официальный | — |
| Схемы | `zod` | Валидация и типы из одного описания; MCP SDK принимает zod-схемы для инструментов | JSON Schema вручную |
| Frontmatter | `yaml` (eemeli) + свой парсер разделителей | Минимум зависимостей, строгий YAML 1.2 | `gray-matter` (тащит устаревший js-yaml) |
| Повторения | `ts-fsrs` (стабильная 5.x) | Реализация FSRS от авторов алгоритма; 6.0 пока в beta | Свой SM-2 (хуже по эффективности) |
| Сборка | `esbuild` → один файл `dist/*.mjs`, **коммитится в репозиторий** | При установке плагина нет шага сборки, `npm install` пользователю не нужен | tsc без бандла (нужны node_modules у пользователя) |
| Тесты | `vitest` + MCP-клиент SDK in-process + `claude plugin eval` | Быстро, ESM-нативно | jest |
| Линт и формат | `eslint` + `prettier`, `tsc --noEmit` в CI | Стандарт | — |
| CI | GitHub Actions: lint, typecheck, unit, integration, проверка, что `dist` собран из текущих исходников, `claude plugin validate --strict`; evals — вручную или по метке (стоят денег) | | |

**Риск стека:** у пользователя Claude Code может не быть Node (нативный установщик Claude
Code его не требует). Варианты снижения риска — в §10.

## 9. Технические ограничения (честно)

1. **Поведение модели не гарантировано.** «Не писать готовый код» и «записывать
   доказательства» — это инструкции skills. Мы измеряем, насколько часто они выполняются
   (evals), но не гарантируем 100%. Жёстко гарантировать можно только то, что делает код:
   формат, правила уровней, безопасность.
2. **Чат claude.ai** — без хуков и локального MCP. Только методика без памяти (§3.4).
3. **Skill может не активироваться** на неочевидные формулировки, особенно на смеси языков.
   Описание skill нужно тщательно подобрать под RU и EN и проверить evals.
4. **Контекст:** карточка ≤ ~2k токенов, SKILL.md ≤ 5k токенов (иначе обрежется после
   компакции). Много дисциплин → в карточке только активные.
5. **Модель не знает точную дату** → даты ставит только сервер.
6. **Транскрипт Claude Code** пишется асинхронно, его формат — внутренний и может меняться.
   Поэтому `reflect` — опциональная функция, а не основа.
7. **Cowork:** в документации не уточнено, какой Node runtime использует локальный MCP из
   плагина в Cowork (spike S2).
8. **Несколько параллельных сессий** пишут в одни файлы → нужны блокировки и атомарная запись.
9. **Evals дорогие:** каждый прогон — реальные вызовы модели (×3 прогона ×2 ветки
   с плагином и без), плюс LLM-судья.
10. **Авторское право:** в библиотеке источников храним только свои конспекты, ссылки и
    короткие цитаты.

## 10. Риски и способы их снижения

| # | Риск | Вероятность / влияние | Снижение |
|---|---|---|---|
| R1 | Режим наставника «протекает» в рабочие проекты и Claude отказывается писать код | высокая / критическое | Активация только в учебной папке (§5.1), без `force-for-plugin`; eval «вне учебной папки код пишется как обычно» |
| R2 | Модель забывает записывать прогресс | средняя / высокое | Протокол контрольных точек в skill; перезагрузка карточки после компакции; nudge-хук (фаза 4); eval с `tool_used: mentor_record_evidence` |
| R3 | Завышение уровней («прочитал → знает») | средняя / высокое | Типы доказательств + правила в коде; `exposure` и `self_report` не повышают уровень; evals |
| R4 | Чрезмерная строгость, пользователь бросает обучение | средняя / высокое | Лестница помощи, настраиваемая строгость, явный выход из режима; рубрика «тон поддерживающий» в evals |
| R5 | Порча файлов (ручная правка, сбой, параллельные сессии) | средняя / высокое | Валидация при чтении, атомарная запись (tmp + rename), lock-файл, журнал, карантин, `doctor`, резервная копия перед миграцией и удалением |
| R6 | Prompt injection из веб-источников | средняя / высокое | Сабагент-исследователь без права записи, сводка вместо сырого текста, валидация `save_source`, правила в skill, eval с «отравленной» страницей через mock |
| R7 | Нет Node у пользователя Claude Code | средняя / среднее | Проверка в хуке с понятным сообщением; документация; в фазе 6 оценить Node SEA или bun-бинарники (не в `bin/`) |
| R8 | Утечка персональных данных или секретов в профиль | низкая / высокое | Фильтр секретов (паттерны ключей и токенов) при записи; skill «не сохранять PII»; PRIVACY.md с описанием того, что хранится |
| R9 | Потеря данных при удалении плагина | средняя / высокое | Данные вне `${CLAUDE_PLUGIN_DATA}`; README предупреждает |
| R10 | Изменения платформы (поля манифеста, хуки) | средняя / среднее | Минимум экзотических функций; `claude plugin validate --strict` в CI; README с минимальной версией Claude Code |
| R11 | Несовместимость формата данных между версиями | средняя / высокое | `schema` в каждом файле, миграции вперёд с бэкапом, тесты на фикстурах старых версий; правило: minor-версия плагина не ломает формат |
| R12 | Конкуренция со встроенным Learning mode | высокая / среднее | Позиционирование на памяти, модели знаний и наставнике по коду (§2.3, §4) |
| R13 | Стоимость токенов на пользователя | средняя / среднее | Компактная карточка, ленивые запросы через инструменты, исследование по TTL, progressive disclosure в skills |

## 11. Стратегия тестирования (кратко; подробно — в ARCHITECTURE.md)

| Уровень | Что проверяет | Инструмент | Когда |
|---|---|---|---|
| Unit | схемы, правила уровней, FSRS-обёртка, DAG, path guard, фильтр секретов, миграции | vitest | каждый коммит |
| Integration | MCP-сервер целиком через SDK-клиент на временной папке; повреждённые и отсутствующие файлы; параллельная запись; экспорт и удаление | vitest | каждый коммит |
| Hooks | вывод `SessionStart` в учебной папке и вне её, лимит размера, поведение при повреждённых данных | vitest (запуск `hook.mjs` как процесса) | каждый коммит |
| Manifest | `claude plugin validate --strict` | CLI | каждый коммит |
| Behaviour (evals) | 13 сценариев ТЗ + педагогические рубрики, сравнение с прогоном без плагина | `claude plugin eval`, `llm`-грейдеры с PASS/FAIL-критериями, `history_file` для многоходовых сценариев, mock-MCP для оффлайна и «отравленных» источников | перед релизом, по метке в PR, `--max-cost-usd` |

Соответствие сценариев ТЗ:
1 новая тема → проверка пререквизитов, этапы, нет кода на старте ·
2 продолжение → использует карточку, не переспрашивает известное ·
3 долгий перерыв → начинает с повторения просроченного ·
4 хорошее понимание → не повышает уровень без самостоятельного применения ·
5 повторяющиеся ошибки → фиксирует заблуждение, а не случайную ошибку ·
6 просьба о готовом коде → не даёт решение, предлагает первый шаг, тон доброжелательный ·
7 не понимает → другая аналогия, шаг назад ·
8 несколько дисциплин → не смешивает данные ·
9 переход между чатами → состояние из файлов ·
10 оффлайн → честно сообщает, работает по кэшу ·
11 устаревшие источники → помечает, сверяет версии ·
12 повреждённые файлы → `doctor`, карантин, работа продолжается ·
13 экспорт и удаление → полный экспорт, удаление с подтверждением.
Дополнительно: **вне учебной папки Claude пишет код как обычно** (R1).

Педагогические рубрики LLM-судьи (каждая с PASS/FAIL): «ответ заканчивается одним вопросом
или заданием, а не пятью», «нет полного решения исходной задачи», «аналогия сопровождается
пояснением, где она перестаёт работать», «длина ответа соответствует уровню», «тон без
снисходительности».

## 13. Как лучше выпустить продукт

1. **Отдельный публичный репозиторий** (например, `learning-mentor`). Сейчас работа ведётся в
   папке `learning-mentor/` текущего репозитория, потому что сессия привязана к нему; перенос с
   историей — `git subtree split --prefix=learning-mentor`. **Создание публичного репозитория и
   публикация — только после вашего подтверждения.**
2. **Имя:** `learning-mentor`, `displayName: "Learning Mentor"`. Имена с `claude-`,
   `anthropic-` и т.п. зарезервированы валидатором. Имя после релиза менять нельзя.
3. **Репозиторий = маркетплейс:** `.claude-plugin/marketplace.json` с `source: "./"`. Установка:
   ```bash
   claude plugin marketplace add <owner>/learning-mentor
   ```
   ```bash
   claude plugin install learning-mentor@<marketplace-name>
   ```
4. **Версионирование:** semver плагина в `plugin.json` (поднимать при каждом релизе, иначе
   пользователи не получат обновление) **и отдельно** `schema` формата данных. Миграции
   только вперёд, с резервной копией. Изменение формата данных → minor с миграцией; удаление
   поля → major.
5. **Бета:** собственный маркетплейс, 5–10 пользователей, сбор обратной связи через GitHub Issues.
   Встроенной телеметрии нет и не будет.
6. **Публичный релиз:** подача в Anthropic Directory (нужен платный план claude.ai,
   pre-submission checklist). Одна запись доходит до claude.ai, Cowork и Claude Code. В README
   честно описываем различия между поверхностями.
7. **Лицензия:** MIT (проще всего для сообщества и совпадает с аналогами) или Apache-2.0
   (явная патентная оговорка). Рекомендую MIT, решение за вами.
